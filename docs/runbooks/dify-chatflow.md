# Dify Chatflow 配置与部署

本手册仅用于配置云函数的 Dify 接入。真实 Dify 调用和开发云环境执行均依赖用户在其开发云环境中完成变量配置；未配置或无可用开发云环境时，保持本地模拟模式，不能将本手册视为真实连通验证。

## 云函数环境变量

仅在 CloudBase 的云函数环境变量中配置下列名称，不在小程序代码、本地配置文件、测试资料、日志或 Git 中填写其值：

| 用途 | 环境变量名称 |
| --- | --- |
| 两套 Chatflow 的共同服务地址 | `DIFY_BASE_URL` |
| 自由问答 Chatflow 凭据 | `DIFY_CHAT_API_KEY` |
| 行程定制 Chatflow 凭据 | `DIFY_TRIP_API_KEY` |

在微信开发者工具的“云开发”控制台中，进入目标云环境的“云函数”，选择 `aiService`，在其“配置/环境变量”位置设置上述三个变量。变量只属于该云函数运行环境；不要将它们写进 `config/local.json`、前端构建参数或任何客户端可访问的数据集合。

`DIFY_BASE_URL` 直接填写 Dify“访问点”页面显示的 API Endpoint（例如 `https://api.dify.ai/v1`），也可以填写不带 `/v1` 的服务根地址。云函数会规范化地址并补上 `/chat-messages`，不要把完整的 `/v1/chat-messages` 请求路径填入环境变量。只有两套应用确实使用不同服务地址时，才额外配置可选覆盖项 `DIFY_CHAT_API_BASE_URL` 与 `DIFY_TRIP_API_BASE_URL`。

## Chatflow 输入准备

自由问答与行程定制是两套独立 Chatflow。两者都必须创建可选的文本输入变量 `local_verified_facts`，供云函数写入本地已核验地点资料；该变量不由小程序发送，也不应在页面展示原始内容。

行程定制 Chatflow 的首次生成还必须配置以下五个输入变量：

- `destination`
- `people`
- `totalBudgetCny`
- `days`
- `preferences`

其中 `preferences` 由云函数转为逗号分隔文本。后续行程调整只沿用原有行程上下文，不重新提交这五个首次表单字段。

## 部署顺序

1. 在两套 Chatflow 中完成上述输入变量配置，并确认变量均为可选文本输入（首次行程的五个字段按应用需要接收）。
2. 在目标开发云环境为 `aiService` 设置 `DIFY_BASE_URL`、`DIFY_CHAT_API_KEY` 和 `DIFY_TRIP_API_KEY`；不要在界面截图、共享文档或提交记录中保存值。
3. 在同一环境创建 `ai_sessions`、`ai_messages` 和 `trip_requests` 集合，并设置为仅管理员可直接访问；普通用户只能经云函数读取自己的记录。
4. 将 `aiService` 的执行超时设置为 120 秒。保存后回到配置页，确认显示“120 秒”。
5. 部署 `aiService` 云函数及其依赖的 `ai` 模块到同一云环境。
6. 使用体验构建调用自由问答和行程定制各一次，再分别进行一次后续提问或调整，并打开“AI 问答记录”确认两类结果均可读取。
7. 仅在结果、错误提示、历史记录和云函数运行状态均符合预期后，安排真实云端与真机验收。

## 验证两类会话隔离

不要打印、截图、记录或向客户端返回任何会话上下文标识。可用不可识别的测试问题验证：先在自由问答中给出一个仅用于本次测试的偏好，再追问该偏好；随后在行程定制中提交不同偏好并追问。两边的后续回答应各自延续本功能内的上下文，不能引用另一边的测试信息。

接着执行“新对话”，确认自由问答不再延续其先前上下文，而行程定制的后续调整仍能延续；再执行“重新规划”，确认只清除行程定制上下文。验收记录只写这些可观察结果、功能类别和时间，不写任何标识值。

## 无密钥回滚

若需立即停止真实 Dify 调用，在 CloudBase 的 `aiService` 环境变量配置中移除三项必需的 Dify 配置（以及可能存在的两项地址覆盖），或部署先前不调用真实服务的云函数版本。随后重新部署并验证页面显示可理解的不可用提示；不要填入替代凭据，也不要以模拟成功掩盖真实服务失败。

恢复本地开发时，不配置这些变量即可继续使用开发模拟模式。真实 Dify、开发云环境、网络、双用户隔离与真机验证均须待用户提供并配置可用的开发环境后单独执行。
