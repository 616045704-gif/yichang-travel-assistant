# Dify Chatflow 配置与部署

本手册用于把已经发布的自由问答 `chat` 和行程定制 `trip` 接入微信云开发。整个过程只在腾讯云控制台的遮罩输入框中粘贴凭据；不要把任何真实值、账号标识或会话标识写进聊天、文件、截图、命令、日志或 Git。

## 部署前确认

1. 登录**拥有目标微信小程序的腾讯云账号**。如果账号不匹配，先切换账号，不要在错误账号下新建同名资源。
2. 进入“云开发 CloudBase”，选择这个小程序实际使用的目标环境。核对环境名称即可，不要在验收记录或截图中展示账号、环境或用户标识。
3. 确认小程序前端只通过 `wx.cloud.callFunction({ name: 'aiService' })` 请求 AI。前端不得直接访问 Dify，也不得包含 Dify 地址或凭据。

## 配置三个环境变量

4. 在目标环境依次打开：**云函数 → `aiService` → 函数配置 → 环境变量**。
5. 只新增下表中的三个名称，并按“控制台值来源”回到对应产品页面复制：

   | 环境变量名称 | 用途 | 控制台值来源 |
   | --- | --- | --- |
   | `DIFY_BASE_URL` | 两套 Chatflow 共用的服务地址 | Dify 公共 HTTPS API Endpoint；可以带或不带 `/v1`，但不得带 `/chat-messages` |
   | `DIFY_CHAT_API_KEY` | 自由问答鉴权 | 已发布的 `chat` 应用 API 凭据 |
   | `DIFY_TRIP_API_KEY` | 行程定制鉴权 | 已发布的 `trip` 应用 API 凭据 |

6. 每个值只粘贴到控制台对应的**遮罩字段**中。两个应用的 API 凭据不要交换。不要在聊天、源码、本地配置文件、共享文档、截图、命令、数据库、日志或 Git 中临时保存这些值。
7. 如果配置页中还存在旧版的“按 Chatflow 单独覆盖服务地址”项目，删除这些旧版覆盖项。两套 Chatflow 必须共用经过核验的 HTTPS 服务地址。
8. 点击保存。保存后只核对三个环境变量**名称存在**，不要显示、复制或宣读它们的值。
9. 将 `aiService` 的云函数执行超时设置为 **120 秒**。代码对单次 Dify blocking 请求的截止时间保持 **45 秒**，为本地资料查询、重试和记录事务留出余量。

## 核对 Chatflow 输入

10. 在已发布的 `trip` Chatflow 开始节点确认首次行程使用以下五个自定义输入变量：

    - `destination`
    - `people`
    - `totalBudgetCny`
    - `days`
    - `preferences`

11. 确认 `chat` 和 `trip` 两个 Chatflow 都配置可选文本变量 `local_verified_facts`，用于接收云函数提供的本地已核验地点资料。它不由小程序用户填写，也不在页面原样展示；`trip` 另有步骤 10 的五个首次行程字段。
12. `chat` 和 `trip` 均继续使用 Chatflow 内置的 `query` 作为当前用户消息。首次 `trip` 发送上述五个字段；后续行程追问只发送新的 `query`，不重复提交首次表单。

## 创建数据库集合与索引

13. 在同一个 CloudBase 环境创建或确认以下四个集合：

    - `ai_sessions`
    - `ai_messages`
    - `trip_requests`
    - `usage_counters`

14. 将四个集合的直接访问权限全部设为 **`ADMINONLY`**。普通用户只能经过云函数访问自己的数据，不要放开客户端直读或直写。
15. 分别为 `ai_messages` 和 `trip_requests` 创建历史查询联合索引，字段顺序和方向必须完全一致：`ownerId ASC + createdAt DESC + _id ASC`。
16. 按目标 CloudBase 环境实际支持的 TTL 生命周期策略，以 `expiresAt` 为到期字段，仅删除已过期的 `usage_counters`。如果当前套餐或控制台不支持所需 TTL 规则，将自动清理记录为待办并保留现有数据；不要误删未到期计数器，也不要让客户端删除计数器。

## 构建与部署

17. 在本地完成正式演示构建、客户端边界检查和文档检查，确认小程序包内没有 Dify 地址、凭据或前端网络直连。
18. 构建并部署 `aiService` 及其依赖。部署或更新函数配置时选择**保留现有环境变量**，不要用本地配置覆盖控制台中已经保存的三个变量。
19. 部署完成后再次进入环境变量页面，只核对三个名称仍存在，并确认云函数超时仍为 120 秒；不要查看或复制值。

云函数会先查询本地 `published` 地点资料，再把已核验资料作为上下文传给 Dify。本地资料优先于 Dify 补充内容。自由问答和行程定制分别使用独立会话与独立历史集合，重置其中一类不会清除另一类。

## 无标识冒烟验证

20. 使用不包含姓名、手机号、位置或其他可识别信息的测试内容，依次验证：

    1. `chat` 首次自由问答成功，并能在历史页看到原问题和回答。
    2. `trip` 首次行程使用五个表单字段成功，历史页显示行程摘要和回答。
    3. `trip` 后续追问能延续本类会话，不重新发送五个首次字段。
    4. “新对话”只重置 `chat`，“重新规划”只重置 `trip`，两类会话互不串线。
    5. 重复提交同一请求能读取安全缓存，不产生重复行程或回答。
    6. 模拟网络不可用或 Dify 超时后，页面显示可理解的不可用/重试提示，不显示空白页或模拟成功。
    7. 同一用户一分钟内超过 3 次新请求时被明确拒绝，已成功的历史仍可查看。

21. 验收记录只写“功能类别、测试时间、可观察结果、是否通过”。不要打印、复制、截图或记录用户标识、请求标识、Dify 会话标识、尝试令牌、环境变量值或数据库内部标识。

## 无密钥回滚

22. 若新版本异常，先在 CloudBase 把 `aiService` 回滚到上一个已验证版本。回滚部署时仍选择保留现有环境变量，随后重复最小冒烟验证。
23. 若必须立即停止真实 Dify 调用，只在 `aiService` 的环境变量配置中移除上述三个必需变量并保存。页面应显示可理解的“暂时不可用，请稍后重试”，不得用模拟结果伪装成功。
24. 回滚或停用后仍不要导出、打印或截图任何配置值。恢复时由有权限的操作者在遮罩字段内重新配置，并从步骤 8 开始复核。

本手册只说明无密钥部署步骤，不代表已经完成真实云端、双用户隔离或真机验收；这些结果必须以目标环境中的实际测试记录为准。
