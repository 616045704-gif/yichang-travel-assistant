## 本次变更

- Dify `trip` 当前为“开始 → 一次知识检索 → 快速行程生成 → 最终回复”。没有并行、多轮 AI、循环或工具调用。
- 开始节点包含可选文本 `local_verified_facts`；快速节点优先使用该资料，并将一次知识检索结果仅作补充。
- 已删除旧的并行知识检索、变量聚合、旧模型和旧回复节点。
- 快速节点使用 `deepseek-v4-flash` 聊天模型，最大输出为 900；模型的“思考模式”参数已启用并显式设为关闭；记忆窗口为 3。
- 云函数对 `trip` 的 `local_verified_facts` 截断到 Dify 开始字段的 256 字符限制；`chat` 仍保持 4000 字符上限。
- 云函数在 Dify 响应边界剥离完整的 `<think>…</think>` 推理块和 Dify 推理注释；只有最终正文可进入小程序与历史记录。
- 行程表单和“我的 → 旅行偏好”均向 WXML 提供显式 `{ value, selected }` 状态，点击后立即同步可见选中状态。

## 行程限额与错误提示修复（待部署）

被测代码提交：`3923db2`（`fix: allow normal consecutive AI requests`）、`3547f6a`（`fix: explain trip request rate limits`）

### 根因与修复范围

- 2026-09-06 小程序真实链路日志显示云函数在约 331ms 内返回 `RATE_LIMITED` 和安全提示“请求较频繁，请稍后再试。”。这不是 Dify 超时或腾讯云网络故障。
- 原代码将 `submitAi()` 抛出的所有云函数错误都显示为“网络连接不稳定，请重试”，因而错误地掩盖了限流原因。
- 项目自设的用户维度限额由每固定分钟 3 次、每个上海自然日 20 次调整为每固定分钟 6 次、每日 50 次。相同请求 ID 的缓存重放和既有的一次逻辑重试不会重复扣减限额。
- 行程页仅对白名单安全消息“请求较频繁，请稍后再试。”原样展示；未知异常仍显示原网络重试文案。Dify 工作流、模型、密钥、环境变量和前端调用边界均未修改。
