# 团队测试交接规则

## 已确认分工

用户在“三峡旅游小助手”任务中明确要求组建团队，并补齐前端、后端、测试。约定是测试角色在每个模块完成后验证。2026-09-04 用户在当前任务再次指出专职测试没有参与，本文件落实原有分工。

产品、UI、前端、后端、测试、统筹是项目职责。先前的方案阶段确有角色参与，但这不代表每次后续改动已经经过对应角色验收。不得只凭设计文档中的角色表声称团队已执行任务。

## 模块交接

1. 开发负责人完成改动与自测，提供被测 Git commit、范围、运行方式和已知限制。
2. 独立测试负责人根据需求实际执行可运行的检查，复核页面与异常路径，记录缺陷和未测项；不能只转述开发者的测试结果。
3. 代码审查负责发现实现与维护问题；代码审查结论和测试验收结论分别记录，不能互相替代。
4. 开发负责人处理阻断问题，测试负责人对修复后的版本复验。报告标注实际被测 commit，不把旧报告用于后来变更的代码。
5. 统筹交付时分别说明开发自测、代码审查、独立测试及真机验收状态。缺少任何必要证据时明确待验，不把阶段通过写成完整产品通过。

纯文档调整运行文档及引用检查，在提交说明中注明自动化行为测试不适用；应用代码与 UI 修改必须有独立测试交接。

## 验收记录

独立报告保存在 `docs/testing/`，包含角色、被测 commit、日期、实际执行命令与结果、复核证据、缺陷严重度、可放行范围及未执行事项。截图和含账号配置的原始附件留在忽略目录，报告用无敏感信息的摘要记录。

仅可对实际可测范围签署阶段结论。未接入云端地点、个人记录或 Dify 时不验收对应完整功能；模拟器不代替 Android/iPhone 真机、位置授权、数据隔离和扫码体验验证。

四页骨架、透明地图分类与国风主题先前由开发负责人运行测试，另有独立代码审查；专职测试交接遗漏。该遗漏不改变已有测试实际运行的事实，但先前结果不能称为独立测试负责人验收。本次安排独立测试代理重新执行可运行检查，报告单独归档，不追认先前未发生的验收。
