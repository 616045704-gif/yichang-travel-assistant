# 用户提供地点图片绑定前置核对

日期：2026-09-07
范围：当前开发云环境中的用户提供图片绑定批次

## 目标与规则

- 目标清单：25 个已登记地点，合计 75 个用户提供的图片对象。
- 写入规则：第 1 张写入地点封面；第 2、3 张作为详情图片节。
- 非目标：不修改其余地点、集合权限、云函数、Dify、环境变量或密钥。

## 实际核对

| 核对项 | 结果 |
| --- | --- |
| 本地授权清单 | 25 条；四类覆盖为景区 14、餐馆 5、文化馆/博物馆 1、露营地 5；每条恰有 3 个不重复对象名。 |
| 云存储对象 | 75 个清单对象均在当前开发云环境中可见。 |
| 目标 `places` 文档 | 用 25 个目标 ID 筛选得到 25 条；增加 `status = published` 条件后数量仍为 25。页面抽检显示分类与清单一致、坐标系为 GCJ-02。 |
| 配对 `place_contents` 文档 | 用同一组 25 个目标 ID 筛选得到 25 条；抽检显示均保留既有文字 `sections`。 |
| 字段契约 | `placeService` 仅接受 `cloud://` 封面及图片节；生成包使用该格式，并为每条详情保留文字后追加两张图片。 |

## 可恢复性与执行包

- 控制台现有文档在写入前已通过筛选和页面抽检；生成包仅含 25 条目标记录，不含其他地点。
- 生成器会在重跑时移除本批次相同的两条详情图片节，再按固定顺序追加，避免重复图片；原有文字与无关图片不移除。
- 生成文件位于已忽略的本地目录，不纳入 Git、不包含密钥或用户身份数据。

## 阻止项与未测项

- 无阻止项。
- 云端导入与小程序运行验收尚未执行；将在导入后由独立测试角色记录。
