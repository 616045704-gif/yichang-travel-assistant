# 白底编辑风 UI 重构实施计划

## 目标

在不改变任何前端业务行为、云函数、Dify 调用、数据库字段、接口参数、路由或定位授权时机的前提下，将整个小程序重绘为白底、图片优先、现代旅行编辑风界面；顶栏与 Tab 为白色，紫色仅作为小面积交互强调，并替换现有图标为统一原创的精细图标系统。

## 约束

- 仅修改 `miniprogram/` 的 WXML、WXSS、现有本地图标，以及相应前端静态测试和验收记录。
- 保留全部 `bind*` 事件、`wx:if` 状态分支、页面数据字段、服务调用、错误文案、收藏/记录写入条件和 AI 安全提示。
- 不新增地点资料、网络图片或生成图片。只有数据已有 `coverUrl` 时显示图片；无图时提供中性回退表面。
- 图标以 24px 网格、圆端线条、统一留白和少量旅行紫实心重点重绘；不使用 emoji、Unicode 图形、大色块底座或外部素材。

## 执行步骤

1. 先更新视觉静态测试，使它断言白色导航/Tab、白底令牌、克制紫色、图片回退和图标资源路径，同时继续断言 Tab 页面顺序与服务边界不变。
2. 重建全局令牌、应用壳和原生导航配置：纸白、雾白、墨紫、旅行紫、浅紫、细分割线；移除深紫整屏与亮黄主按钮用法。
3. 重绘四个 Tab、四类地点、地图针及共享控件图标，并由 SVG 导出保持同名 PNG；图标路径和尺寸契约不变。
4. 重做共享组件：地点卡改为编辑列表行与真实图片/中性回退；筛选、异步状态、提示、消息和来源组件统一白底与细线层级，不改变属性、事件或状态条件。
5. 按阅读优先级重构首页、发现、地图、地点详情：图片、标题、信息行与轻操作组成层级，保留已有绑定、地图手势与地点跳转。
6. 用同一规范重构我的、记录、偏好、隐私、AI 聊天、AI 历史和行程表单；保留隐私、错误、重试、表单校验和 AI 免责声明。
7. 运行单元测试、类型检查、lint、构建与包检查；在可用的微信自动化环境逐页截图。没有自动化终端或真机时，验收记录明确为未测，不冒充通过。
8. 对最终应用改动执行独立代码审查和独立测试记录，再按聚焦的 Conventional Commit 提交。

## 交付顺序

1. `feat: establish white editorial travel theme`
2. `feat: refine editorial travel icon system`
3. `feat: restyle editorial travel pages`
4. `test: verify white editorial travel UI`
5. `docs: record white editorial travel UI QA`

## 验收清单

- 顶部和底部 Tab 均为白色，旅行紫未成为整屏/整卡背景。
- 每个页面有明确的图片、标题、正文、行动层级，不形成同质卡片堆叠。
- 图标风格一致，且所有原有图标引用仍可读取。
- 加载、空、错误、禁用和提示状态保留现有行为并可读。
- 云函数、服务层、数据库、Dify、接口、路由和业务 TypeScript 逻辑无功能性变更。
