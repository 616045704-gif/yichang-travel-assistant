# 批量导入用户整理地点资料设计

## 目标与范围

将用户提供的单张 Dify 知识库 Excel 批量转换并写入微信云开发现有的 `places` 与 `place_contents` 集合。首批全部 387 条记录在受控微信体验版中公开展示，供地图、地点详情、自由问答和行程定制使用。

本次是用户明确要求的范围调整：不再限制首批仅 20–30 条精选地点，也不新增内容审核后台、第三张内容集合或新的数据库服务。Excel 原文件不上传进小程序包、不提交 Git；导入过程只在管理端运行。

## 资料口径

每条导入记录的公开来源统一显示为“向半斗整理收集”。这是资料整理归属，不伪装成景区、商户或政府的官方核验来源。地点详情和 AI 页面继续显示“内容仅供出行参考，请以景区、交通等官方公告为准”。

原表中的价格参考、营业时间、设施、车位和攻略属于用户整理的参考资料，允许在详情页展示，但必须带上述提示。AI 收到本地上下文时将其标为“用户整理的本地参考资料”，不能称为“官方已核验资料”，不得把其中易变信息表述为保证、实时状态或预约承诺。

## 数据映射

单张工作表的每一行生成同一 `placeId` 的两份文档：

| Excel 列 | `places` 映射 | `place_contents` 映射 |
| --- | --- | --- |
| 类别、餐类 | 四类 `category` 与 `tags` | `diningInfo` 的补充标签 |
| 名称、所属景区 | `name`、`aliases` | 详情标题文本 |
| 城市/区县、地址、经纬度 | `district`、`address`、GCJ-02 坐标 | - |
| 内容 | `intro`（截短摘要） | 主文本段落 |
| 攻略/建议 | - | `visitAdvice` |
| 价格参考、营业时间、设施/服务、车位信息 | `openNotice` 的统一提示 | 参考资料文本与 `notices` |
| 标签 | `tags` | - |
| 信息更新时间、数据来源 | `updatedAt`、公开整理来源 | 同步 `updatedAt` |

类别映射固定为：景区概览、子景点映射 `scenic`；博物馆/文化馆映射 `culture`；餐馆映射 `restaurant`；露营地映射 `camping`。车位信息不新增地图分类，而是保留在关联地点详情。

导入器对名称、地址和坐标生成稳定、可重复的 `placeId`；同一行重复导入更新原文档而不产生副本。无封面图时写入 `coverFileId: null`，前端继续使用现有无图降级样式。

## 发布与权限

所有成功转换的记录写入 `status: "published"`，使现有列表、地图和 AI 检索立即可用。不能解析名称、四类类别、有效中国坐标或正文的行会被拒绝，不产生半条记录；导入报告列出其行号和原因。

`places` 与 `place_contents` 继续保持 `ADMINONLY`，小程序只能调用现有云函数取得字段白名单投影。Dify API Key、CloudBase 凭据、用户身份、用户位置和 Dify 会话标识不写入 Excel 导出、地点集合、前端或日志。

为了支持用户整理来源，内容校验将允许已发布地点使用一个明确的用户整理来源条目和空封面，但仍要求名称、分类、地址、坐标、摘要和时间字段完整。该例外不适用于用户记录或 AI 凭据，也不把资料提升为官方核验等级。

## 导入执行与回退

导入前先在本地完成 Excel 读取、字段映射、坐标解析、重复 ID 检测和内容验证。通过后，由仅管理端可运行的受控导入器对 `places` 与 `place_contents` 执行按 `placeId` 的 upsert。导入器输出总数、四类数量、更新数和拒绝行，不输出整条资料、密钥、账号、环境完整标识或用户资料。

写入前，导入器为会被覆盖的地点生成受控备份。失败时不发布部分批次；已写入但验收失败时，将本批地点恢复备份或改为 `draft`，不得清空集合、删除用户收藏、浏览记录或 AI 历史。

## 验收

1. Excel 的有效行全部导入，四类总数与转换报告一致。
2. 列表、地图和详情只经云函数读取 `published` 记录；无封面资料正常显示降级样式。
3. 同一 Excel 再次导入不会增加地点数。
4. 每个分类抽检一条：名称、地址、坐标、长内容与参考提示正确。
5. 真实 AI 请求先检索导入地点；返回内容把本地资料说明为用户整理参考，并保留官方公告提示。
6. 小程序包、云函数日志和 Git 中不含 Dify API Key 或管理端凭据；普通客户端不能直读或写入地点集合。

## 非目标

- 不建立商家后台、审核工作流、停车场独立分类、自动抓取官方网页、图片导入或公开运营发布。
- 不把用户整理来源改写成官方来源，不承诺价格、营业时间、交通时刻、预约或实时可用状态。
- 不修改现有 Dify 应用、模型、知识库或 API Key。
