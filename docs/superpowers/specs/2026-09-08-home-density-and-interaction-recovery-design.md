# 首页密度与交互恢复设计

## 目标

根据最新截图收紧首页视觉密度，并把真实点击验证补入交付流程。保持现有路由、页面方法、云函数、Dify、数据库、接口和数据字段不变。

## 已确认根因

- `app.json` 仍注册全部二级页面，Home、Discover、Map 和 Me 的导航方法及 WXML 绑定均存在。
- 直接调用 `openAiChat` 可进入 `/pages/ai-chat/index`，说明路由本身有效。
- 最近两个提交没有修改导航实现；现有静态与单元测试均通过。
- 微信开发者工具的当前输入/运行实例存在点击未分发或上下文不同步现象，旧 `wechat-smoke.mjs` 又仍使用已经删除的选择器，因此此前验收没有覆盖真实点击。

本轮不以修改导航函数或堆叠 `z-index` 掩盖现象。先重开项目并重新编译，再以更新后的冒烟脚本和开发者工具逐条验证。

## 视觉方案

### 色彩与字阶

- 纸白：`#FFFFFF`，继续作为导航与主要内容底色。
- 页面淡紫：`#F8F7FB`，用于页面背景与分隔。
- 主紫：`#7454D8`，继续用于选中态和小面积强调。
- 地点标题保持 `34rpx / 750`；分类文字继续使用原有深色 `22rpx / 650`，不另行改色。

### 首页布局

```text
┌──────────── 当前头图 + 出发吧 ────────────┐
└──────────────────────────────────────────┘

   [ 90% 自由问答图 ]    [ 90% 行程定制图 ]
          两侧留白、中央 24rpx 间距

│ 分类
   本地景区图标   本地餐馆图标   本地博物馆图标   本地露营地图标
      深色文字       深色文字         深色文字        深色文字

┌──────────────── 大图地点 ────────────────┐
└──────────────────────────────────────────┘
地点名称（左，可换行）             收藏图标 + 文字（右）
```

- AI 图片保持用户提供的内容，不裁掉内部文字；显示宽度改为按钮的 `90%`，图片本身圆角和轻阴影，按钮仍保留完整点击区域。
- 分类图标必须使用用户放在 `icon+banner` 中的现有插画，不重绘、不改配色；显示尺寸只从 `112rpx` 放大到 `128rpx`。
- 底部四个原生 Tab 必须继续使用用户提供的选中/未选中图标。原生 Tab 的图标框尺寸由微信控制，因此仅裁掉派生 PNG 内部的透明留白，把原画在固定图标框中放到最大安全尺寸，不改图案。
- 地点标题与收藏使用同一 `card-meta` 水平行。标题区域和收藏按钮是同级节点，避免收藏点击冒泡打开详情；收藏仍保留至少 `80rpx` 触控高度。

## 交互与错误处理

- Home 的 AI、分类和地点事件名与导航方法不变。
- Discover 与 Map 的原生 picker 事件合同仍为 `categorychange: { category }`。
- 更新微信冒烟脚本，使用 `.home-hero`、`.ai-quick-card`、`.category-select`、`.place-card` 和当前地图结构。
- 冒烟脚本必须点击自由问答并断言页面路径，点击地点卡并断言详情路径，打开 picker 后以组件方法验证分类映射；自动化端口不可用时必须标记待验，不能声称通过。

## 验收标准

1. 地点名称与收藏在同一水平行，收藏不遮挡图片或标题。
2. 两张 AI 图视觉宽度为原卡片约 `90%`，两图之间有明显留白且仍可整卡点击。
3. 分类和底部四个 Tab 均使用用户本地提供的图标；分类图标显示为 `128rpx`，Tab 派生图减少内部透明留白，分类文字保持深色。
4. 首页 AI、首页分类、Home/Discover 地点详情、Discover/Map picker、Me 二级入口的源码绑定和真实页面路径验证均通过。
5. 微信开发者工具编译无致命错误；未验证的真机或云端路径如实记录。

## 自检

- 无 TBD、TODO 或新增业务入口。
- 不改变接口、路由、数据库、云函数、Dify 或定位授权时机。
- 视觉修改只涉及首页、共享地点卡和分类图标；交互修改只涉及测试脚本与开发者工具运行状态。
