# 三峡旅游小助手现代紫黄 UI 设计说明

## 1. 目标与范围

将小程序统一为“现代高饱和紫黄旅行工具”视觉：以明快的紫色品牌画布、亮黄色操作强调、白色内容卡片和圆润几何图标构成统一体验。参考案例仅用于理解高对比配色、模块化版式、图标节奏和留白；不复制其猫头鹰、插画、图形、文案、界面截图或其他专属资产。

本次仅修改小程序前端的视觉样式、展示结构和项目内原创图标资源。不得修改云函数、Dify 调用、数据库字段、数据库权限、页面业务逻辑、位置授权流程、接口参数或数据来源。现有地点照片、地点文本与 AI 安全提示继续保留。

## 2. 品牌视觉系统

### 2.1 颜色

| 用途 | 值 | 使用规则 |
| --- | --- | --- |
| 品牌紫 | `#623BC7` | 首页主视觉、标题重点、选中控件 |
| 深紫 | `#2B174D` | 原生导航栏、Tab 背景、深色文字、黄色按钮文字 |
| 亮黄 | `#FFC400` | 主按钮、选中 Tab 图标、关键徽标、进度和加载强调 |
| 浅紫 | `#EEE9FF` | 次级按钮、默认标签、输入区弱底色 |
| 雾紫 | `#F8F6FF` | 页面背景 |
| 卡片白 | `#FFFFFF` | 卡片、弹窗、输入框 |
| 正文墨紫 | `#30254A` | 正文和默认图标 |
| 辅助灰紫 | `#746C8B` | 辅助说明、时间、未选中图标 |
| 反馈红 | `#C83F56` | 错误状态和危险操作 |
| 反馈绿 | `#25866C` | 成功确认和可用状态 |

亮黄只承担关键动作与已选中强调，不能大面积铺在长文本或普通卡片上。文本与背景组合必须保持可读性：黄底按钮使用深紫文字；深紫底使用白色或亮黄色文字；白底使用深紫正文。

### 2.2 字体与层级

所有页面使用系统无衬线字体链：`-apple-system`、`BlinkMacSystemFont`、`"PingFang SC"`、`"Microsoft YaHei"`、sans-serif。移除宋体、楷体、印章字、竖排文本、仿古题字及诗句式装饰。

| 层级 | 尺寸 | 字重 | 用途 |
| --- | --- | --- | --- |
| 页面主标题 | 52rpx | 700 | 每页主标题、首页主要标题 |
| 区块标题 | 36rpx | 700 | 列表区块、弹窗标题、详情名称 |
| 卡片标题 | 30rpx | 650 | 地点名、菜单标题、表单标签 |
| 正文 | 28rpx | 400 | 描述、输入内容、消息内容 |
| 辅助信息 | 24rpx | 400/600 | 标签、时间、说明、字数 |

正文行高为 1.6，说明行高为 1.5；连续文本不使用大字距。标题与正文使用固定层级，禁止页面自行定义近似字号。

### 2.3 间距、圆角与表面

采用 8rpx 基础间距：页面左右留白 32rpx，常规区块间距 32rpx，卡片内部间距 28rpx，紧凑控件间距 16rpx。卡片、表单和弹窗使用 28rpx 圆角；胶囊筛选、标签和小按钮使用 999rpx 圆角；地点图片圆角与卡片外框一致。

页面背景为雾紫。普通内容使用白色卡片、`1rpx` 浅紫边框和低对比紫色投影；同一页面不叠加多层卡片阴影。首页主视觉允许使用深紫至品牌紫的渐变，配合原创 CSS 几何江流曲线、峡谷轮廓和定位点，不使用水墨、宣纸或古风插画。

## 3. 原创图标系统

所有 UI 图标改为统一的原创圆润几何填充图标，使用相同的圆角、留白和双色规则。不得保留 emoji、Unicode 箭头或依赖不同系统字体的图形字符。

1. 默认图标为深紫图形配浅紫或白色底。
2. 关键入口使用亮黄圆角方形/圆形底座与深紫图形。
3. 深紫底上的未选中图标使用浅紫，选中图标使用亮黄。
4. 图标内部最少 2rpx 安全留白，圆角与轮廓比例一致，视觉尺寸统一。
5. 图标以项目原创 SVG 保存；原生 Tab 同步导出所需 PNG。不得引用参考页面的猫头鹰、构图或资源。

覆盖范围包括：首页四分类、四个 Tab、搜索、收藏、地图定位与设置、聊天、行程、历史、个人菜单、隐私、来源卡、重试、空状态、成功/错误反馈和所有方向箭头。分类图形分别表达山水路线、餐饮、展馆和露营，但不代表或伪造具体地点资料。

## 4. 共享组件规范

### 4.1 导航

原生导航栏为深紫背景与白色标题；页面不新增自定义导航业务。原生底部 Tab 为深紫背景，默认图标与文字为浅紫，选中图标与文字为亮黄；现有四个 Tab 路径和跳转不变。

### 4.2 卡片、列表与标签

地点卡片使用大图、白色主体、28rpx 圆角和 20rpx 图文分隔。标签采用浅紫底深紫字；收藏按钮使用图标加短文本的紧凑胶囊。详情、记录、来源、AI 消息、偏好和表单卡沿用相同表面规范，不因页面不同而改用古金、纸纹或不同圆角。

### 4.3 按钮与输入

主按钮为亮黄底、深紫文字、至少 88rpx 高，点击态降低亮度；次按钮为浅紫底、深紫文字；轮廓按钮为白底浅紫描边。禁用按钮使用灰紫白底与弱化文字，不能与可点击状态混淆。输入框为白色、浅紫边框、28rpx 圆角；聚焦态显示品牌紫边框或柔和外发光。

### 4.4 筛选、地图与浮层

筛选项使用胶囊按钮：默认白底深紫字，选中品牌紫底白字；黄色不同时作为筛选背景和文字。地图继续展示真实地图与原有 marker 数据，顶部筛选器、定位按钮、提示、设置入口和地点简卡改用紫黄组件。地图浮层保留可见性与手势规则，不能遮断地图拖动或现有定位路径。

## 5. 页面布局

| 页面 | 视觉调整 |
| --- | --- |
| 首页 | 紫色渐变主视觉、原创抽象江流/峡谷几何背景、黄色主入口、现代分类图标宫格、精选地点白卡 |
| 发现 | 统一页面标题、胶囊分类筛选、现代搜索框、地点白卡及资料提示卡 |
| 地图 | 深紫/白色/黄色的透明操作层与地点简卡；地图本体和 marker 数据不变 |
| 我的 | 现代欢迎卡、圆形旅行者徽标和图标菜单；记录入口按同一白卡分组 |
| 地点详情 | 大图、标题与收藏并列、信息块与图片段落使用统一白卡和紫色标签 |
| AI 问答与历史 | 深紫用户气泡、白色助手气泡、黄色发送按钮、来源卡与免责声明采用标准提示组件 |
| 行程表单与偏好 | 白色表单卡、清晰标签/输入层级、胶囊偏好项、统一提交与调整操作 |
| 收藏/浏览记录与隐私 | 使用共享标题、状态组件、列表行、信息卡和辅助说明层级 |

## 6. 状态、弹窗与空白体验

所有已存在状态分支必须视觉完整且与主界面一致；只改呈现，不改状态判定、重试行为、异常消息来源或接口调用。

| 场景 | 视觉与操作要求 |
| --- | --- |
| 初始加载 | 居中紫色轨迹与亮黄点的原创加载指示，配简短加载文字；禁用重复提交按钮 |
| 列表/记录/历史为空 | 白色空状态卡、对应原创图标、明确标题与解释；有既有入口时保留，不虚构数据 |
| 搜索无结果 | 搜索相关图标、保留关键词与筛选条件，提示调整条件；不显示空白区域 |
| 网络或服务错误 | 红色反馈标记、可理解文本、原有重试按钮；不伪造成功或掩盖失败 |
| AI/行程提交中 | 保留消息或表单上下文，显示加载反馈，主操作禁用且不可重复提交 |
| 成功反馈 | 绿色确认标记和短暂、非阻塞确认文案；不改变原有后续跳转与数据写入时机 |
| 收藏等待 | 收藏胶囊显示加载/禁用态，等待既有业务结果后恢复 |
| 定位拒绝/需设置 | 保留现有提示与设置入口，重绘为统一信息卡；地图仍可浏览 |
| 长文、长名称与小屏 | 标题/说明允许换行，按钮不截断，底部 Tab 与安全区不遮挡内容 |
| 弹窗与二次提示 | 若页面已有原生或现有提示，采用白色圆角容器、深紫标题、辅助说明、黄主操作/浅紫取消操作；不新增会影响业务流程的确认步骤 |

## 7. 验收标准

1. 所有页面只使用同一组现代紫黄令牌、无衬线字体、间距、圆角和按钮规范；不残留古风字体、印章、卷轴、宣纸或水墨元素。
2. 原生导航栏、四个 Tab、页面内图标、分类图标与状态图标均属于统一原创紫黄图标体系；不使用 emoji 或参考作品资产。
3. 首页、发现、地图、我的、地点详情、AI、行程、记录、偏好、隐私、AI 历史的正常、加载、空、错误、禁用与必要提示状态均有可读布局。
4. 真实地点内容仍由云端读取，地点照片、定位、收藏、浏览、AI 问答、行程、重试和错误分支的行为不变。
5. 在微信开发者工具逐页截图比对，并运行相关单元测试、类型检查、静态检查、构建、包检查和文档验证；截图与独立测试记录明确已测范围及未测项。
