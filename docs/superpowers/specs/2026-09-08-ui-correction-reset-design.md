# 首页、分类、地图与“我的”页面纠偏设计说明

## 1. 纠偏目的

本轮不是继续探索新风格，而是撤销偏离用户参考图的设计，并按照用户最后提供的截图恢复明确的页面关系。

只修改以下四处：

1. “我的”页面顶部个人信息区域。
2. 发现页和地图页的分类 Tab。
3. 地图地点弹卡的尺寸、对齐与点击。
4. 首页“出发吧”透明度及两张 AI 入口图的对齐。

首页头图、发现头图、地点列表、详情页、底部菜单、“我的”页面下半部分，以及所有未点名页面均不调整。

## 2. 参考图判读

### 2.1 “我的”页面参考

参考：`codex-clipboard-ef6fde22-dc67-4fbd-b096-ac33560820f7.png`。

目标不是用几个低透明度分类图标拼成背景，而是形成一个完整、连续的旅行主题头图区块：

- 外层是浅紫蓝插画背景，横向铺满内容区。
- 左上依次显示“我的旅行”“留下你的出发线索”和一行较弱的说明文字。
- 右侧是山峰、路线、定位点、飞机、路牌等一体化旅行插画，装饰不能压住文字。
- 头图下半部内嵌一张白色半透明个人卡，而不是将个人卡放到头图外。
- 个人卡左侧使用人物头像插画和小飞机徽章，中间是“你好，旅行者”及说明，右侧仅保留轻量手写装饰。
- 页面下方收藏、浏览记录、AI 问答记录、旅行偏好和隐私说明完全不改结构、不改顺序、不改跳转。

当前实现偏差：背景由分类图标和 CSS 图形临时拼接，人物头像实际使用了底部 Tab 图标，视觉上没有形成参考图中的完整插画头图，因此即使代码结构发生变化，成品仍会被感知为“没有改”。

### 2.2 分类 Tab 参考

参考：`codex-clipboard-26f10772-f468-4daa-9b8b-7ce6bc65b7be.png` 及此前提交 `3fb4f2e` 的横向卡片结构。这里恢复的是上图标、下文字、白色圆角卡和浅紫选中态，不机械照搬旧提交在地图可用宽度内无法完整容纳五项的旧尺寸。

恢复为横向五项 Tab：

1. 全部分类
2. 景区
3. 餐馆
4. 文化馆/博物馆
5. 露营地

每项均为上图标、下文字的白色小卡。选中项使用浅紫底、紫色文字和轻描边；未选中项保持白底深色文字。图标继续使用用户本地文件夹中的原图，不重绘、不改颜色、不替换成线性图标。

发现页和地图页共同使用自适应五等分视觉参数：高度 `112rpx`、图标 `56rpx`、圆角 `24rpx`、固定间距 `8rpx`、上下内边距 `8rpx 4rpx 7rpx`。取消普通项固定宽度及“文化馆/博物馆”单独加宽；每项以 `flex: 1 1 0` 均分所在轨道的可用宽度，长标签允许两行居中显示，不使用省略号。两端的边框、背景、阴影、文字间距、字号、行高和选中态必须一致。

发现页默认搜索按钮固定为 `88rpx`，搜索按钮右侧剩余区域必须完整显示五个分类，不得依赖横向滚动；地图页五个分类必须从左至右均分并填满分类栏，右侧不得保留空白占位。搜索展开时可临时压缩分类区，但必须保留明确关闭入口；关闭搜索后立即恢复五项完整展示。

发现页与地图页必须看起来是同一套 Tab，禁止再出现下拉框、胶囊文字筛选、另一套独立按钮或不同尺寸的分类控件。

## 3. 页面设计

### 3.1 “我的”页面顶部

采用一张原创、完整的浅紫蓝旅行插画背景资源，而不是继续使用 CSS 拼图。插画根据用户参考图重新绘制，但不直接复制参考图中的专属素材。

布局：

```text
┌──────────────────────────────┐
│ 我的旅行          山峰 / 飞机 │
│ 留下你的出发线索   路线 / 路牌 │
│ 去看更大的世界……             │
│ ┌──────────────────────────┐ │
│ │ 人物头像  你好，旅行者  装饰 │ │
│ │          收藏灵感……        │ │
│ └──────────────────────────┘ │
└──────────────────────────────┘

下方现有菜单保持不变
```

视觉参数：

- 头图左右与页面内容边缘保持 `20–24rpx` 间距。
- 头图圆角约 `28–32rpx`，高度约 `400–430rpx`。
- 主标题为近黑色粗体，字号约 `42–46rpx`；说明文字使用灰紫色。
- 个人卡左右留白一致，距离头图底边约 `18–24rpx`。
- 个人卡使用约 90% 白色，不使用大面积高饱和紫色。
- 头像必须是人物或旅行者形象，不得使用底部导航“我的”图标代替。

需要新增的视觉资源限定为：一张原创旅行背景图和一张原创人物头像图。其余菜单图标继续使用本地现有资源。

### 3.2 发现页分类

- 搜索入口仍位于横排最左侧，默认只显示小型普通线性搜索图标。
- 点击后在原位置展开；必须提供明确的关闭方式，发送按钮只显示纸飞机图标，无色块大按钮。
- 搜索控件右侧紧接横向分类 Tab；默认状态采用五等分，不左右滚动。
- 搜索未展开时，搜索控件右侧的五个分类必须在首屏完整显示，分类区不允许通过横向滚动隐藏项目。
- 分类 Tab 使用用户本地 `全部、景区、餐馆、博物馆、露营地` 图标。
- 点击区域覆盖完整 Tab 卡，不只覆盖图标或文字。

### 3.3 地图页分类

地图页在视觉上恢复到提交 `3fb4f2e` 的横向 Tab 结构和选中态，不使用当前看起来不同的第二套分类样式；实际尺寸采用 2.2 节规定的一屏五项适配参数。

由于微信小程序原生 `map` 组件具有独立渲染层，地图上的分类控件仍需使用可覆盖原生地图且可接收点击的实现；但其尺寸、圆角、图标、文字、间距和选中态必须与发现页共享 Tab 一致。技术承载方式不得改变用户看到的样式。

地图分类只包含现有五项，不新增停车场或任何业务入口。分类值、筛选请求和定位逻辑保持不变。

### 3.4 地图地点弹卡

弹卡保留“左图、右侧信息”的结构，但扩大有效空间并重新对齐：

- 卡片左右边距一致，底部不与原生 TabBar 重叠。
- 图片使用稳定的方形区域；有地点图片时显示地点图片，无图片时显示统一系统占位图。
- 右侧从上到下为分类、地点名称、查看详情。
- 分类、标题和按钮左边缘对齐，按钮不挤压标题。
- 地点名称最多两行，卡片高度随两行标题仍保持完整。
- “查看详情”使用紫色按钮并填满右侧信息栏宽度；它只占右侧信息栏，不得横向扩展到左侧图片区域或整张卡片宽度。
- 点击地图标记显示卡片，点击卡片按钮进入现有详情页。

地图底部两个操作按钮必须遵守同一套文字与框体对齐规则：

- “定位我的附近”按钮在地点卡上方水平居中，按钮中心线与下方地点卡中心线一致。
- “定位我的附近”的文字必须在按钮框内水平、垂直居中，不得出现文字偏上、偏下或被原生按钮内边距挤压的情况。
- “查看详情”按钮放在地点卡右侧信息栏底部，其左、右边缘与右侧信息栏对齐，不越过图片区域，也不贴住卡片边缘。
- “查看详情”的文字必须在紫色按钮框内水平、垂直居中，文字基线不得下沉，按钮背景、圆角和文字必须作为一个完整控件呈现。
- 两个按钮使用一致的高度、圆角逻辑和文字字号层级；定位按钮为白底紫字，详情按钮为紫底白字，以功能主次区分，而不是通过错位或不同高度区分。
- 两个按钮的可点击热区必须覆盖整个可见按钮框，不能只让文字区域响应点击。

### 3.5 首页指定纠偏

- 首页头图及其图片内容不改。
- “出发吧”保持当前位置，圆角白色背景透明度为 30%，文字本身保持清晰紫色，不随背景一起透明。
- “自由问答”和“行程定制”继续使用用户本地两张大图。
- 两张图等宽、等高，左右外边距相等，中间间距固定；不裁切标题和主体插画。
- 两个入口的完整图片区域均可点击，并继续进入原有页面。

## 4. 交互与业务边界

本轮不得修改：

- 云函数、Dify 调用或配置。
- 数据库字段、集合和云存储接口。
- 页面路由目标、分类值和接口参数。
- 地图定位授权时机、20 公里筛选逻辑和标记 ID。
- 收藏、浏览记录、AI 问答记录和旅行偏好的业务逻辑。
- “我的”页面下半部分的内容、入口顺序和文案。

所有图标和卡片都必须验证真实点击，不以静态选择器存在或单元测试通过代替运行时点击。

## 5. 验收标准

### 5.1 视觉

- “我的”顶部一眼可见完整紫蓝旅行插画和内嵌个人卡，不能再呈现为零散图标拼图。
- “我的”下方菜单与修改前保持一致。
- 发现页和地图页分类均为同一套横向五项 Tab。
- 发现页默认状态下搜索按钮与五项分类同排完整显示；地图页五项等分铺满分类栏且右侧无空白。
- 分类图标全部来自用户本地资源，大小统一，不重绘。
- 地图弹卡图片、分类、标题、按钮具有明确间距，无遮挡、无挤压、左右对齐。
- “定位我的附近”按钮相对下方地点卡水平居中，二者中心线偏差不超过 2px。
- “定位我的附近”和“查看详情”的文字均在各自按钮框内水平、垂直居中，文字视觉中心与按钮框中心偏差不超过 2px。
- “查看详情”按钮边缘与地点卡右侧信息栏对齐，不侵入左侧图片区域，不超出卡片内边距。
- 首页两张 AI 图的宽高差不超过 2px，左右外边距差不超过 2px。
- “出发吧”背景透明度按 30% 呈现，文字仍清晰。

### 5.2 运行时点击

在微信开发者工具完整冷启动后逐项实际点击：

- 首页“出发吧”、自由问答、行程定制。
- 发现页搜索展开、关闭、纸飞机发送和五个分类 Tab。
- 地图页五个分类 Tab、至少两个不同类型点位、地点卡详情按钮。
- 地图“定位我的附近”和地点卡“查看详情”必须点击可用，并分别从按钮框中心位置执行点击验证。
- 底部首页、发现、地图、我的四个 Tab。
- “我的”页面四个业务入口及隐私说明。

热更新状态异常时必须重新冷启动后再验收，不得把点击波纹、静态测试或旧截图记录为通过。

## 6. 实施顺序

1. 用户确认本文档。
2. 编写聚焦的实施计划和对应失败测试。
3. 恢复分类 Tab 视觉并验证运行时点击。
4. 按参考图完成“我的”顶部原创插画资源和布局。
5. 调整地图弹卡及首页指定项。
6. 构建并在微信开发者工具冷启动逐项点击。
7. 保存逐页截图、记录未测项并提交聚焦的 Git commits。

在第 1 步完成前，不修改任何页面源码。
