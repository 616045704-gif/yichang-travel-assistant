# 宜昌旅游 AI 微信小程序设计说明

## 1. 项目目标

构建一款用于面试展示的、可在手机上通过微信小程序体验版二维码运行的宜昌旅游小程序。项目强调产品经理可完成从需求设计、地点内容管理、AI Agent 配置到可运行小程序交付的完整闭环。

首版目标是完成真实可运行的体验版，而非公开运营产品。它采用微信云开发承载后端和数据，随后安全接入用户已有的 Dify 聊天助手。

## 2. 首版范围

### 2.1 核心功能

1. **AI 旅游助手**
   - 自由问答：回答宜昌景点、餐饮、文化与出行相关问题。
   - 行程定制：用户填写目的地、人数、预算、天数和旅行偏好，获得行程建议。
   - 问答历史：用户可在“我的”中查看历史提问和回答。
   - 回答规则：本地地点数据库优先，Dify 知识库负责补充背景与攻略；没有可靠资料时明确说明，不编造。

2. **地点发现与详情**
   - 四个分类：景区、餐馆、文化馆/博物馆、露营地。
   - 列表：封面图、名称、区域或距离、简短介绍、标签、收藏状态。
   - 详情：图文内容、地址、坐标、开放提示、特色标签、推荐游玩时长或餐饮信息、收藏按钮。
   - 首版导入约 20–30 条精选地点资料。地点内容存在云数据库，图片存在云存储，不硬编码到小程序页面。

3. **地图找附近**
   - 默认显示宜昌城区和地点标记。
   - 用户主动点击“定位我的附近”后才申请位置授权。
   - 授权后显示当前位置 20 公里内的四类地点，可按分类筛选。
   - 点击标记先显示简卡，再进入与地点列表共用的详情页。
   - 拒绝定位时仍能手动浏览地图和地点清单。

4. **我的**
   - 收藏、浏览记录、AI 问答记录、基础旅行偏好、隐私说明和反馈入口。
   - 首版不要求手机号登录，不包含支付、购票、预约或商家入驻。

### 2.2 非范围

- 线上支付、票务、预约、团购、交易和营销裂变。
- 复杂运营后台与商家管理。
- 实时交通、实时票价、实时天气等需持续维护的数据服务。
- 自动采集或直接复制其他小程序的文字、图片和数据。
- 首版直接面向全体用户公开发布；先提供受控的微信体验版。

## 3. 用户与展示场景

主要展示对象为面试官。核心演示路径为：

1. 通过体验二维码进入小程序。
2. 浏览宜昌地点清单并查看图文详情。
3. 主动授权定位，查看附近 20 公里的地图点位并进入详情。
4. 收藏地点，回到“我的”查看收藏和浏览记录。
5. 向 AI 询问宜昌旅游问题，或提交行程定制表单并查看建议。

体验前应准备已验证的问题示例、行程案例及备用录屏，避免现场网络或定位异常影响演示。

## 4. 体验与页面设计

2026-09-04 用户预览后明确要求地图页改为大地图与分类切换，移除附近卡片；当前页面布局以[分类大地图调整](2026-09-04-map-first-design.md)为准。

### 4.1 视觉方向

采用“山水文化感 + 轻量现代旅行工具”的原创风格：江水青绿为主色、暖砂金为辅色、米白为大面积背景。使用大图卡片、充分留白、16–20px 圆角、系统字体和简洁线性图标。后续可依据用户提供的参考截图提取配色、排版与信息层级，但不得复制专属图文和视觉资产。

### 4.2 导航与页面

- **首页**：AI 助手主入口、热门地点、分类入口和精选推荐。
- **发现**：四类地点的分类切换、搜索/标签筛选、地点列表。
- **地图**：宜昌地图、分类标记、附近定位、地点简卡。
- **我的**：收藏、浏览记录、AI 问答记录、偏好、隐私和反馈。
- **地点详情**：四类地点共用同一图文详情页面。
- **AI 助手**：自由聊天与“我要定制行程”双入口。
- **行程表单**：目的地、人数、预算、天数、偏好及结果展示。

AI 页面需显示“内容仅供出行参考，请以景区、交通等官方公告为准”。

## 5. 技术架构

```text
微信小程序（页面、表单、聊天、地图）
        ↓
微信云函数（安全后端）
  ├─ 查询云数据库与云存储地址
  ├─ 筛选 20 公里附近地点
  ├─ 管理收藏、浏览与问答记录
  └─ 以环境变量中的凭据调用 Dify
        ↓
Dify 聊天助手（现有知识库与模型）
        ↓
返回回答和来源标记给小程序
```

这是前后端分离架构：小程序前端不直接接触 Dify API Key；云函数是后端边界；Dify 是外部 AI 编排与知识库服务。

## 6. 数据设计

### 6.1 云数据库集合

| 集合 | 用途 |
| --- | --- |
| `places` | 四类地点的名称、分类、地址、坐标、标签、简介、开放提示、图片地址、资料来源和最后核验时间 |
| `place_contents` | 较长图文详情、游玩建议、注意事项 |
| `favorites` | 用户收藏的地点与收藏时间 |
| `browse_history` | 用户最近浏览的地点；同一地点保留最近一条 |
| `ai_sessions` | AI 会话摘要和 Dify 会话标识 |
| `ai_messages` | 用户提问、AI 回答、时间与参考来源标记 |
| `trip_requests` | 行程表单输入及生成结果 |
| `feedback` | 地点资料纠错、AI 回答反馈和意见建议 |
| `app_settings` | 首页推荐、AI 调用限额等可配置项 |

地点图片上传至云存储，数据库只保存图片地址。用户资料类集合仅允许用户通过云函数访问自己的记录；公共地点资料由后端读取。

### 6.2 初始地点资料

首版使用约 20–30 条经过确认的资料，四个分类均有覆盖。用户可提供 Excel、链接、文档、截图或地点名称清单。资料优先采用官方公开信息或用户确认的内容；图片必须拥有使用权或来自可商用素材来源。

## 7. AI 设计与接入顺序

### 7.1 开发阶段

1. 先完成所有小程序页面、云数据库、地图、收藏、记录及 AI 页面交互。
2. AI 页面开发阶段使用模拟回答，验证发送、加载、失败、历史和行程表单体验。
3. 小程序主体稳定后，才配置并接入用户现有的 Dify 聊天助手。
4. 将模拟回答替换为真实 Dify 回答，完成真机全链路测试。

不会复刻、迁移或替换用户已有的 Dify Agent、知识库、模型或提示词。

### 7.2 数据库优先规则

云函数收到自由问题或行程表单时：

1. 提取地点、分类、人数、预算、天数等条件。
2. 先查询 `places` 和 `place_contents`。
3. 将命中内容标记为“本地已核验资料”，与用户问题一起发送给 Dify。
4. Dify 的系统规则要求优先采用本地资料；知识库只补充文化背景、攻略和出行建议；出现冲突时以本地资料为准。
5. 回答带来源提示并保存必要历史；资料不足时明确说明不确定。

首版复用 Dify 聊天助手即可实现该流程。未来如需要严格可审计的顺序控制，再将 Dify 升级为“数据库查询 → 知识库检索 → LLM 汇总”的工作流，前端和云函数调用边界保持不变。

## 8. 安全、隐私与内容规则

- Dify API 地址和 API Key 仅由用户在云函数环境变量中配置，绝不写入前端代码、数据库或版本库。
- 位置仅在用户主动点击定位后读取，仅用于当前 20 公里筛选，默认不长期保存。
- 用户可拒绝位置授权，拒绝后仍可浏览默认地图与清单。
- 微信上线或体验前，按实际使用的位置能力填写用户隐私保护指引。
- AI 接口设置单用户调用频率、单次输入长度和输出长度限制，控制成本并防止滥用。
- Dify 不可用、网络异常或资料不足时，展示可理解的提示与重试入口，不显示空白页或伪造成功。
- 公开内容不直接复制其他小程序，易变信息需标记资料来源和最后核验时间。

## 9. 团队职责与模型策略

| 角色 | 职责 | 默认模型策略 |
| --- | --- | --- |
| 产品负责人 | 需求、用户流程、范围与验收 | Terra，中/高推理 |
| UI/交互负责人 | 视觉规范、信息层级、交互 | Terra，中推理；常规文案可用 Luna |
| 前端负责人 | 小程序页面、组件、地图与状态 | 常规页面 Luna，中推理；关键交互 Terra |
| 后端负责人 | 云函数、数据库、Dify、安全与权限 | Terra，高推理 |
| 测试负责人 | 真机、异常、隐私、演示验收 | Terra，高推理；批量测试资料用 Luna |
| 项目统筹 | 协调角色、汇报、变更管理 | Terra，中/高推理 |

Terra 用于架构、关键逻辑和审核；Luna 用于明确且重复的页面、资料整理和文案任务。

## 10. 验收标准

体验版可用于面试展示的最低门槛：

1. 四类地点均可从列表和地图进入共用详情页，内容来自数据库而不是前端硬编码。
2. 授权定位后只显示约 20 公里范围内的地点；拒绝授权不会中断地图和清单。
3. 收藏、浏览和 AI 问答记录均可在“我的”中查询，退出后仍能读取。
4. 自由问答和行程定制均具备完整 UI 流程；Dify 接入后，两者可真实完成调用。
5. Dify API Key 不出现在小程序代码、网络请求、日志或页面中。
6. AI 对已命中的地点优先使用本地资料；无可靠资料时不虚构易变信息。
7. 无网络、Dify 超时、空数据、权限拒绝和接口错误均有用户可理解的提示。
8. 至少在一台 Android 与一台 iPhone 真机完成“定位 → 详情 → 收藏 → AI 提问”的连续演示测试。
9. 体验二维码、已授权体验成员、示例问答、示例行程和备用录屏在面试前完成检查。
