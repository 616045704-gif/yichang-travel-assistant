# 有封面地点优先展示设计

## 目标

在“发现”页的每个分类、搜索或标签筛选结果中，优先展示已绑定云存储封面的已发布地点，让首屏首先呈现可用图片，同时保留全部地点资料。

## 根因与范围

现有地点仓储按名称排序全部 387 条已发布地点，而本阶段只有用户确认的 25 条资料拥有 `coverFileId`。排在前面的无封面地点会按既有界面显示“图片暂不可用”；云函数对已绑定地点已能返回可加载的封面和详情图片 URL。

本次不上传或修改图片、不写云数据库、不改云函数名称、环境变量、Dify、密钥或权限。地图标记和详情读取顺序也不变。

## 行为

`placeService` 的列表仓储在完成现有发布状态、分类、关键字和标签筛选后，按以下稳定键排序：

1. `coverFileId` 为非空字符串的地点在前；
2. 同一封面状态内继续按地点名称和地点 ID 的现有排序规则排列。

分页继续基于这个最终顺序产生游标，因此翻页不重复、不遗漏。没有封面的地点仍会出现在后续页，原有占位文案保留为真实缺图状态。

## 验证

新增仓储单测：混合有封面与无封面的已发布地点时，有封面地点先返回，且后续游标仍能读取无封面地点；现有筛选与草稿排除行为保持。运行相关单测、类型检查、静态检查、构建、包检查和文档检查；由独立测试角色复验并记录未覆盖的开发者工具/真机检查。
