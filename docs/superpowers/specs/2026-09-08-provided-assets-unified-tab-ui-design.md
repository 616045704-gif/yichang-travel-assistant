# 三峡旅游小助手：用户提供资源的四 Tab 视觉重构设计

## 目标与范围

在不改变任何业务逻辑、数据字段、接口、云函数、Dify 调用、地图 SDK、定位授权时机、页面路由或事件绑定的前提下，使用用户提供的 `icon+banner` 资源，将首页、发现、地图、我的重构为统一的现代旅行助手界面。

设计以白色为主、旅行紫为少量品牌强调色；拒绝大面积紫色块、厚阴影、后台菜单感和默认小程序控件感。用户提供的插画承担品牌识别，地点数据库已有的 `coverUrl` 仍承担真实地点内容的图片展示。

## 资源策略

原始资源位于 `D:\ChatGPT\宜昌旅游助手\icon+banner`，均保持原样，不移动、不改名、不直接打包进小程序。

| 用途 | 原始资源 | 运行时处理 |
| --- | --- | --- |
| 首页 Hero | `首页头图.png` | 保留图片内“峡江胜境·诗画宜昌”字样；按首页 Hero 比例裁切和压缩。页面不重复叠加同义大标题。 |
| 发现 Hero | `发现头图.png` | 无文字背景，裁切为横向 Hero；标题和辅助说明由 WXML 叠加。 |
| 首页快捷入口 | `自由问答.png`、`行程定制.png` | 裁取插画主体，输出成同规格小图，置于 Hero 下方并列入口。 |
| 分类入口 | `景区.png`、`餐馆.png`、`博物馆.png`、`露营地.png` | 与现有四个分类一一映射；不新增未被业务数据支持的停车场分类。 |
| Tab | `首页.png`/`首页-选中.png`、`发现.png`/`发现-选中.png`、`地图.png`/`地图-选中.png`、`我的.png`/`我的-选中.png` | 裁取中心视觉主体并导出小尺寸透明或白底轻量 PNG，继续由原生 `tabBar` 使用。 |
| 收藏 | `未收藏.png`、`已收藏.png` | 导出小尺寸状态图，作为列表和详情的同一收藏视觉。 |
| 我的菜单 | `已收藏.png`、`浏览记录.png`、`AI 问答记录.png`、`旅行偏好.png` | 裁取主体，作为现有四个菜单入口的统一菜单图标。 |

`意见反馈.png` 暂不接入：当前项目没有对应页面、路由、菜单项或事件绑定；本次不以视觉重构为由新增功能入口。

所有派生资源输出至 `miniprogram/assets/` 的专用目录。运行时资源必须经裁切、缩放、压缩并通过 `node scripts/check-package.mjs` 对 `dist/miniprogram` 执行的 `1_900_000` 字节硬上限；不直接使用当前每张约 0.8–2.7 MB、1254px 以上的原图。新增派生资源合计目标不超过 700 KB，其中两张 Hero 合计不超过 450 KB，Tab、分类、收藏与菜单图标合计不超过 250 KB。

## 视觉令牌

| 名称 | 值 | 用途 |
| --- | --- | --- |
| 纸白 | `#FFFFFF` | 导航、Tab、卡片和主页面表面 |
| 雾白 | `#F8F7FC` | 浅色背景、图标底座和空状态 |
| 墨紫 | `#1F1D2B` | 标题和高优先级正文 |
| 灰紫 | `#827A93` | 辅助说明、未选中标签和弱提示 |
| 旅行紫 | `#7454D8` | 选中态、链接、图标重点和少量按钮 |
| 日光黄 | `#F6C644` | 仅用于极小的状态点或插画呼应，不作整块背景 |

页面水平边距统一为 `32rpx`；Hero 圆角 `28rpx`，图片与常规卡片圆角 `20–24rpx`；模块间距 `32–40rpx`。标题、正文、说明分别使用清晰的三档字号与字重，避免通过多层装饰标签制造层级。

## 页面设计

### 首页

```text
白色原生导航

┌─────────────────────────────┐
│ 首页头图（含“峡江胜境·诗画宜昌”）│
│                         [浏览] │
└─────────────────────────────┘

旅行助手
┌──────────────┐ ┌──────────────┐
│ 自由问答插画  │ │ 行程定制插画  │
│ 自由问答      │ │ 行程定制      │
│ 景点与出行建议│ │ 按偏好规划    │
└──────────────┘ └──────────────┘

从哪里开始（四类分类入口）
值得停留（地点卡片）
```

- Hero 使用带字资源作为唯一的首屏主标题视觉；只叠加轻量的“浏览所有地点”操作，不再保留割裂的顶部标题区。
- 自由问答和行程定制从页面底部移到 Hero 下方，保留原有 `openAiChat`、`openTripForm` 绑定与文案语义；两个入口等宽并列，不新增功能。
- 分类仍仅展示已有的景区、餐馆、文化馆/博物馆、露营地四类，保持原有分类事件与字段。
- 精选与发现页共用同一地点卡片组件。

### 发现

- 使用 `发现头图.png` 作为横向 Hero。右侧或底部仅叠加简短的“发现宜昌”说明，图片不承载文字。
- 分类筛选与搜索保持原有顺序、事件和数据绑定，改为紧凑的浅色表面，避免大块灰底。
- 地点清单复用首页相同的 `place-card`：封面约占行宽 40%，标题优先，行政区/类别为轻标签，简介两行截断。
- 空、加载、失败与资料说明保留现有分支和文案，仅同步视觉令牌。

### 地图

- 地图保持页面核心，占据主要可视区域；不添加会遮挡地图的大 Banner。
- 分类筛选以轻量浮层停靠地图顶部；定位操作、授权拒绝提示、设置入口和地点浮卡均使用白色表面、细边框、旅行紫行动色。
- 点位点击、定位、地图手势、详情跳转和距离筛选不改动。

### 我的

- 顶部为简洁旅行档案区，保留既有用户信息文案；不引入登录或新账户逻辑。
- 我的收藏、浏览记录、AI 问答记录、旅行偏好使用用户提供的对应插画裁切图；隐私说明保留为独立轻量操作。当前没有既有的意见反馈入口，因此 `意见反馈.png` 不接入本轮。
- 菜单行使用统一图标尺寸、基线、分割线和箭头，不使用厚重卡片堆叠。

### 地点卡片与收藏

- 首页精选与发现列表使用同一个横向大图地点卡片。封面高度与信息区对齐，标题不会换到收藏操作之下。
- 收藏按钮放在封面右上角的半透明小圆底中，使用用户提供的已收藏/未收藏状态图；保留现有收藏请求、禁用、加载和事件。
- 详情页收藏操作复用同一视觉资源，但不改收藏逻辑、详情字段或资料来源展示。

### 导航与状态

- 顶部导航和底部 Tab 保持白色。原生 `app.json` Tab 顺序、页面路径和选中状态逻辑不变，仅更新导出图标路径。
- 不创建 custom-tab-bar，以避免改变 Tab 生命周期、跳转和安全区行为。
- 加载、空、错误、弹窗提示和禁用状态保留原有组件和条件；只使用新令牌、间距和轻量插画/图标呈现。

## 实施边界

允许修改：WXML 视觉结构、WXSS、`app.json` 中既有 Tab 图标路径、本地静态资源、资源处理脚本、前端视觉测试与验收记录。

禁止修改：任意云函数、服务调用、Dify 配置或调用、数据库字段、接口参数、页面路径、`bind*` 行为、地图与定位逻辑、筛选/收藏/搜索/记录业务判断。

## 验证与协作

1. 独立 UI 审查角色先审查本设计及资源映射，特别检查首页带字 Hero、发现无字 Hero、四类分类边界、共享卡片和原生 Tab 的兼容性。
2. 用户确认本设计后，主智能体统一实施，不分散修改业务模块。
3. 主智能体运行相关单元测试、类型检查、Lint、构建、包体积检查和资源引用检查。
4. 独立测试角色在交付前验证四个 Tab、地点列表/收藏、地图浮层、加载/空/错误/提示状态，并记录实际提交、执行结果、缺陷和未测项。
5. 微信开发者工具会话若再次提示“调试器加载错误”，记录为环境阻断；不将其误报为页面视觉通过。

## 设计自检

- 首页带字 Hero 是用户明确选择，与“所有标题由代码叠加”的旧要求存在已知例外，首页不再重复叠加大标题。
- 发现 Hero 保持无文字，符合代码叠加文字的规则。
- “停车场”“全部”原图存在，但当前可用业务分类没有停车场；本次不新增筛选值或数据含义。
- “意见反馈”原图存在，但当前没有反馈页面或入口；本次不新增页面路径、菜单项或绑定。
- 所有四个主 Tab 都纳入设计；地图因功能优先不强行添加 Banner。
- 运行时只引用派生资源，原始资源不进入主包。
