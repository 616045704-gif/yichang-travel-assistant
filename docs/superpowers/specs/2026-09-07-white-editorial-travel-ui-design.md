# 宜昌旅行白底编辑风 UI 设计说明

## 1. 目标与范围

将现有小程序重构为面向周末与短途出行用户的现代旅行编辑工具：界面以白色内容面、真实地点图片、清晰文字层级和节制的紫色操作锚点组织信息。它不是紫色品牌海报，也不是古风文旅页，更不是把每项内容包在相同圆角卡片中的通用模板。

本次仅修改小程序前端视觉、布局、原创图标和展示用文案层级。不得改动云函数、Dify 调用、云数据库字段/权限、接口参数、数据来源、定位授权时机、路由、收藏/记录/AI/行程业务条件或错误处理分支。

## 2. 视觉原则

### 2.1 色彩

| 令牌 | 值 | 使用方式 |
| --- | --- | --- |
| 纸白 | `#FFFFFF` | 页面、原生导航栏、底部 Tab、主要内容面 |
| 雾白 | `#F8F7FB` | 极少量分区与空状态背景 |
| 墨紫 | `#29243A` | 标题与正文 |
| 旅行紫 | `#7454D8` | 选中图标、链接、输入焦点、操作状态与极少量主操作 |
| 浅紫 | `#F0ECFF` | 已选筛选、轻提示、弱交互表面 |
| 日光黄 | `#F6C644` | 进度、成功提示和图片中的局部提示；不得作为大面积页面底色 |
| 分割线 | `#EAE6F1` | 信息分组和列表行分隔 |

顶部导航栏和底部 Tab 始终为白色，默认 Tab 图标/文字为灰紫，选中态为旅行紫。紫色覆盖面积应明显小于页面可视面积的 10%；不使用深紫整屏、紫色 Hero 或整块紫色功能卡。

### 2.2 字体与结构

使用系统无衬线字体链：`-apple-system`、`BlinkMacSystemFont`、`PingFang SC`、`Microsoft YaHei`、sans-serif。标题以较紧凑的字距和 700/800 字重建立层级，正文 400/500 字重、行高 1.6。

不使用全大写英文眉标、英文装饰性标签、诗句式宣传文案、宋/楷/仿古字体、印章、卷轴、水墨、纸纹或大面积装饰渐变。文字只承担导航、说明或操作含义。

### 2.3 图片优先

真实地点的 `coverUrl` 与详情图片是情绪主角。首页和列表只在已有图片数据时展示大图/缩略图；无图片时显示安静的中性占位状态，不伪造地点风景、不新增外部图片来源，也不以抽象紫黄渐变代替真实地点图片。

## 3. 图标与控件

所有图标保留项目原创 SVG 与 PNG 导出资源，使用精细圆角线性骨架配少量实心旅行紫重点：线宽、端点、留白和视觉重心统一。Tab 和分类图标不再使用大色块方形底座；选中态用紫色路径/局部填充表达，而非整块底色。

搜索、收藏、方向、地图针、个人菜单、加载、空状态、错误和提示采用同一 24px 视觉网格。图标仍不使用 emoji、Unicode 图形或参考作品资产。

主操作只在提交、保存、发送、重试等明确行动上使用紫色；列表操作、收藏、返回和查看详情采用文字链接或轻量图标按钮。按钮不使用无意义箭头文字，交互名称清楚说明结果。

## 4. 页面布局

| 页面 | 重构规则 |
| --- | --- |
| 首页 | 白底标题与当前出发主题起始；已有精选地点图片承担视觉主角；四分类改为轻量图标导航；AI 问答与行程为两条清晰入口，不做深色/大色块功能卡 |
| 发现 | 标题、单线搜索与轻量筛选先行；地点采用缩略图 + 名称 + 区域/简介的编辑列表，通过细线分隔，不堆叠重阴影卡片 |
| 地点详情 | 已有封面图靠上展示，信息正文以白底、标签和分隔线连续阅读；收藏为轻量紫色操作，图文和资料说明不再被拆成相同卡片 |
| 地图 | 保留全屏地图与原有手势/定位路径；筛选和地点简卡为白底轻量浮层，选中与定位仅用旅行紫提示 |
| 我的、记录、偏好、隐私 | 移除深色欢迎卡和多层卡片；使用标题、简洁说明、原创建议图标和白底分组行 |
| AI、历史、行程 | 白底对话/表单阅读区；用户消息、选中态和明确提交操作使用紫色小面积强调，助手内容与资料来源保持安静白底；不改免责声明、重试或提交状态 |

页面内容采用左对齐阅读轴，连续信息通过留白、图片比例、字号和 1rpx 分割线建立节奏。圆角只用于图片、输入和必要的可触控容器，按层级使用 16rpx/20rpx/24rpx，不再全局使用相同的大圆角和投影。

## 5. 状态与反馈

loading、空状态、错误、重试、提交中、收藏等待和成功/失败反馈保持既有状态与事件，只重绘其表面：白色面、旅行紫状态锚点、清晰原因和可见操作。错误仍使用红色语义色；成功保留绿色语义标识；不新增确认步骤或改变自动跳转/写入时机。

## 6. 前端设计自检

本方案的独特性来自“沿江旅行的阅读节奏”：真实地点图片作为一页中的单一强元素，标题、地点信息和行动链接以由宽到窄的层次推进。它拒绝以下泛化做法：紫色渐变 Hero、统一圆角卡片网格、无意义大写英文眉标、虚构抽象封面、通用阴影和装饰箭头。

实现后必须逐页检查：白色系统栏、紫色覆盖比例、真实图片缺失回退、列表长文本、正常/加载/空/错误/禁用/反馈状态，以及保留所有现有服务调用与用户数据边界。
